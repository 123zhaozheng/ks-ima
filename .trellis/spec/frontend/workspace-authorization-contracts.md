# Workspace Authorization Frontend Contracts

## 1. Scope / Trigger

Apply this specification to member workspace navigation, workspace settings,
members, invitations, groups, folder permission editing/preview, platform
workspace creation, and their generated API/component/browser tests.

## 2. Signatures

```text
src/utils/identity-client.ts                  # single generated DTO transport
src/pages/WorkspaceOverview.vue               # members/groups/directory tabs
src/components/FolderAclDialog.vue            # role/group/user ACL editor
src/admin/pages/WorkspacesPage.vue             # explicit initial admin
tests/components/WorkspaceOverview.vitest.ts
tests/e2e/identity.pw.ts

bun run generate:api
bun run test:unit
bun run test:e2e
```

Workspace payloads use generated `components['schemas']` types. Components call
the central client and never redefine workspace roles, ACL DTOs, or HTTP error
shapes.

## 3. Contracts

- Platform creation requires an explicit active `initialAdminUserId`; the
  logged-in platform operator is not silently made a content member.
- Workspace settings exposes complete member add/invite/revoke/role/state/remove/
  leave, group lifecycle, and directory permission workflows. It renders stable
  loading, empty, error, archived, access-revoked, and version-conflict states.
- `FolderAclDialog` loads the effective ACL and searchable role/group/user
  subjects, groups actions by subject, preserves action dependencies, shows the
  inheritance source, sends one bounded versioned replacement, and reloads on
  conflict. It never uses JSON `entity.conf.acl` as mutable state.
- Manual invitation links appear only in the issuance result, remain visible
  until deliberately dismissed/copied, and never appear in later invitation
  lists, browser storage, logs, or URLs generated by the client.
- UI capability checks are usability only. Viewer/nonmember/platform-role
  journeys assert API denial separately; hidden buttons are not authorization
  evidence.
- The remaining legacy tree may consume target-derived read decisions during
  coexistence, but workspace/member/group/ACL writes use Python exclusively.

## 4. Validation & Error Matrix

| Condition | Required UI/result |
|---|---|
| Session/workspace pending | stable loading; no premature denial |
| Viewer opens settings | readable workspace state; no mutation controls |
| Nonmember platform admin opens workspace | content request 404 |
| Member/group list empty | explicit empty state and available permitted action |
| SMTP unavailable invitation | manual-link notice; never "sent" |
| ACL inheritance enabled | effective source shown; entry editing disabled/derived |
| ACL save returns 409 | visible conflict and reload path; no local success |
| Access revoked while open | clear unavailable state and no stale mutation |
| Generated Problem Details | safe typed message; no raw response/token logging |

## 5. Good / Base / Bad Cases

- Good: the ACL editor selects a group, validates its action set, saves once with
  `expectedVersion`, then refreshes effective entries.
- Good: a workspace admin receives a manual invitation link once and the pending
  list displays only safe user/role/expiry metadata.
- Base: a viewer sees the workspace name/member role but no add, invite, group,
  or ACL actions.
- Bad: derive content access from `platformRoles` or a hidden menu.
- Bad: retain a Zero mutation behind the new workspace settings button.
- Bad: call `/workspaces/*` with local `Record<string,unknown>` response casts.

## 6. Tests Required

1. Vitest mounts the real workspace page and asserts concrete administrator and
   viewer rows/controls/errors, not only `wrapper.exists()`.
2. ACL component/client tests cover role/group/user subjects, inheritance,
   dependent actions, manual invitation display, and 409 reload behavior.
3. Full Playwright uses real Python/PostgreSQL and covers all workspace roles,
   nonmember platform admin, group/direct grants, inheritance, stale ACL,
   archive/revoke, and cleanup with zero skips.
4. OpenAPI export/generation/drift, ESLint, `vue-tsc`, Bun/Vitest, and front/admin/
   server builds pass after any contract or component change.

## 7. Wrong vs Correct

### Wrong

```ts
if (session.user.platformRoles.includes('platform_admin')) showFolderAcl()
await mutate(mutators.updateEntityConf({ id, updates: { acl } }))
```

### Correct

```ts
type AclReplaceRequest = components['schemas']['AclReplaceRequest']
const result = await identityClient.replaceWorkspaceFolderAcl(workspaceId, folderId, {
  inherit,
  entries,
  expectedVersion: acl.version,
} satisfies AclReplaceRequest)
if (result.error?.status === 409) await reloadAcl()
```
