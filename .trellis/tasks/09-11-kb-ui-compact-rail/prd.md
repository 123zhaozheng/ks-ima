# 知识库界面改版：紧凑侧栏与文档操作图标化

## 背景

两处 UI 观感问题（用户反馈）：

1. **左侧栏过宽**：`.app-rail` 宽 240px、每项「图标 + 文案」横排，占用过多横向空间。用户希望改成
   参考腾讯 ima 的**紧凑侧栏**（窄、图标为主、更精致）。
2. **文档操作按钮不统一**：文档预览头部按钮中，有的「图标 + 中文」（如「询问这篇文档」「替换」「保存」），
   有的仅图标（关闭/历史/下载/预览/删除），视觉杂乱。用户要求**统一为纯图标 + 悬浮提示**，
   并把最常用的三个固定为 **保存 / 询问 / 下载**，第四个 `…` 图标点击后**下拉**收纳其余功能。

## 目标

1. 左侧栏改为紧凑样式，横向更省空间、观感更精致。
2. 文档操作按钮统一为图标按钮（无可见文字），悬浮显示提示；前三个固定为 **保存、询问、下载**，
   其余功能收入 `…` 下拉菜单。
3. 把该设计理念写入前端 spec，作为后续同类界面的约定。

## 需求与约束

- **紧凑侧栏**
  - 折叠/展开语义保留：宽屏常驻、窄屏可开合（既有 `uiStateStore.mainDrawerOpen` / `mainDrawerBreakpoint`）。
  - 目标宽度显著小于现状（240px）——建议约 72px 的图标栏（图标在上/文案在下或纯图标 + 提示）。
  - 知识库切换器保留可达性（头像 + 菜单弹层）。
  - 导航项保留 `data-testid`（`rail-nav-ask` / `rail-nav-kb` / `rail-nav-settings` 等）以免破坏 e2e。
  - 管理控制台入口的可见性规则不变（管理员角色）。
- **文档操作按钮**
  - 一律纯图标，`title`/`q-tooltip` 提供中文提示（无可见文字标签）。
  - 固定顺序：**保存、询问、下载**（保存保持主色/强调）。
  - 其余（替换、历史、预览、编辑/预览切换、删除）收入 `…` 下拉菜单；删除保留下拉内负向样式。
  - 保留既有禁用/加载/权限（`readonly`、`kind`）条件与 `data-testid`（`doc-close-button`、
    `doc-ask-button`、`doc-delete-button`）。
  - 关闭按钮（左侧）保持独立图标位置。
- 不改后端与 API；不改文档数据流。
- Chrome 109 兼容（无 CSS 嵌套、`color-mix()`、`oklch()`、容器查询）。
- 颜色/圆角/间距使用 `--tk-*` token。
- 更新 spec：`ux-design-language.md`（紧凑侧栏 + 图标优先操作 + 溢出菜单理念）。

## 验收标准

- [ ] 左侧栏明显变窄，宽屏下不再横排占 240px；导航项可点、有提示、`data-testid` 保留。
- [ ] 文档头部按钮：无中文可见标签；悬停有中文提示；前三个为 保存 / 询问 / 下载；
      第四个 `…` 下拉包含替换、历史、预览、编辑/预览切换、删除。
- [ ] 各按钮的禁用/加载/只读条件与既有行为一致（只读文档不显示删除/保存等）。
- [ ] `bun run lint`、`bunx vue-tsc --noEmit`、`bunx vitest run`、`bun test` 通过；
      相关组件测试更新（断言图标按钮与下拉项存在）。
- [ ] `ux-design-language.md` 已记录该设计理念。

## 非目标

- 不改知识库三栏的整体信息架构（树 / 列表 / 预览）。
- 不改移动端断点逻辑之外的路由或数据。
- 不重做配色/主题系统。
