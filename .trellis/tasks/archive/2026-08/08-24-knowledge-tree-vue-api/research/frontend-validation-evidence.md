# Research: frontend validation evidence for the knowledge-tree API migration

- Query: Map the retained Vue/Quasar/Zero knowledge-tree workflows and the existing versioned Python API, then identify UX/API acceptance gaps and an executable validation matrix for tree depth, pagination, conflicts, cycles, ACL non-disclosure, notes, tags, trash, migration idempotency, OpenAPI drift, and cleanup.
- Scope: mixed (internal code, migrations, tests, and dependency/version evidence)
- Date: 2026-08-25

## Findings

### Existing frontend behavior and anchors

- The retained app is Vue 3 + Quasar 2.16.0, Pinia 3, TanStack Vue Query 5.85.5, Zero 0.26.1, Vitest 3.2.4, Playwright 1.55.0, and `openapi-typescript` 7.8.0 (`package.json:38-112`). The only shared Vue Query setup is `src/boot/vue-query.ts:4-17`; it uses a 30-second stale time, one retry, and no focus refetch.
- The workspace/tree state is still Zero-first. `src/stores/workspace.ts:2-7,17-18,45-59` loads workspaces and the full workspace through `useQuery` from the Zero composable, then preloads entity children, entity ACLs, chats, items, and assistants through Zero. `src/utils/zero-session.ts:16-31,51-60` recreates a Zero client on session changes.
- `src/components/FolderTree.vue:89-109` queries `queries.workspaceFolders` and filters knowledge folders locally. It builds a parent map and recursively flattens expanded rows (`:110-162`), with ancestor expansion from the current route (`:126-149`). This supports a visible deep tree but has no server pagination, explicit loading/error/empty state, keyboard tree semantics, or versioned API adapter.
- The directory view has explicit upload and drag/drop affordances (`src/views/DirView.vue:6-49,90-123,180-191`). `src/utils/knowledge-upload.ts:16-48` recursively walks `webkitGetAsEntry()` and falls back to `DataTransfer.files`; `:66-106` creates missing folders one mutator at a time and creates Zero items while the blob upload is tracked separately. There is no API idempotency key or transaction spanning folder creation, item creation, and blob upload.
- The list exposes breadcrumbs, folder navigation, pagination, drag/drop, multi-select, rename/move/trash, ACL and tags (`src/components/EntityList.vue:10-57,67-82,229-328`). The initial child page is 40 rows and the continuation is 80 rows (`:278-318`); the cursor is the last local child (`:319-327`). The implementation filters ACL-visible entities and knowledge types in the browser (`:295-298`).
- Entity drag/drop uses a custom `application/x-entity-id` payload and directly calls the Zero `moveEntities` mutator (`src/components/EntityList.vue:333-376`). It rejects only self-selection client-side; cycle prevention is delegated to the server Zero mutator (`src-shared/mutators.ts:689-736`). Dropping files invokes the upload helper instead of a versioned content API (`EntityList.vue:354-376`).
- Multi-select is click-to-toggle once selection mode is active, with context-menu activation (`src/components/EntityList.vue:380-388,479-493`). There are no `keydown`, Shift-range, Ctrl/Meta-range, roving tabindex, or screen-reader tree/list semantics in the component. `EntityItem.vue:1-53` renders a `q-item`; its selection indicator appears only after selection mode (`:39-51`).
- Tags are currently a JSON `conf.tags` array edited as a comma-separated string and sent through `updateEntityConf` (`src/components/EntityList.vue:544-560`). This has no normalized tag identity, uniqueness, concurrency/version field, search/list endpoint, or generated API contract.
- Trash is a Zero query with cursor pagination (`src/components/TrashList.vue:67-108`) and selection/context-menu restore/delete actions (`:110-155`). Empty trash calls the legacy `deleteEntities` mutator from `src/layouts/TrashLayout.vue:69-84`. Folder descendants are not modeled as a versioned trash resource in the current Vue path.
- Existing route structure is entity-type based (`src/router/routes.ts:20-43`), including `/folder/:id` via `DualViewPage`, and `/trash` (`:59-68`). There is no route for a note document, file resource, tag view, or API-backed folder detail state. `src/components/EntityList.vue:20-46` supplies breadcrumb buttons and an up-arrow but not a dedicated API breadcrumb query.

### Existing Zero/query/mutator contracts and risks

- Zero query filtering and cursor shape are defined in `src-shared/queries.ts:9-43,100-124,126-136,280-295`; child queries order by `sortPriority`, then the selected `id/name` order, and use `entityStartSchema` (`src-shared/utils/validators.ts:71-99`). The current cursor contract is therefore not directly compatible with the Python `orderKey/version` folder DTO without a mapping.
- The entity schema is legacy and mutable in JSON: `src-server/schema/schema.ts:97-119` has `rootId`, `parentId`, `name`, `conf`, `sortPriority`, `hidden`, and no lifecycle/version/order-key column. Item content is in a separate legacy table (`:233-248`), while Markdown pages and append-only patches are separate (`:187-211`). There is no normalized tag table in this schema.
- Zero folder creation and item creation are independent mutators (`src-shared/mutators.ts:513-542,590-606`). Move has server-only recursive cycle checking (`:689-736`), but recycle/restore/delete operate against the legacy trash entity and do not carry an expected version (`:934-985`). The server Zero adapter performs ACL checks for mutation targets (`src-server/zero/mutators.ts:7-17,20-68`), while browser query results are filtered by Zero permissions.
- The Zero mutator explicitly rejects mutable ACL updates, identifying Python as the sole ACL authority (`src-server/zero/mutators.ts:41-50`). This is an important coexistence boundary: folder ACL UI must use Python endpoints before removing the Zero list/mutation path.

### Existing versioned Python API and database guarantees

- Versioned folder DTOs already expose `workspaceId`, `parentId`, `name`, `orderKey`, `lifecycle`, `version`, `isRoot`, and `aclAnchorId` (`backend/src/ima/api/v1/workspace_contracts.py:98-107`). Create, rename, move, reorder, trash, restore, permanent delete, ACL, and breadcrumbs are registered in `backend/src/ima/api/v1/workspaces.py:324-375,378-508,510-600`.
- Folder reads list only metadata-visible children and return 404 for an inaccessible parent (`backend/src/ima/application/authorization.py:1050-1075`). Breadcrumbs first resolve the visible set and return `FOLDER_NOT_FOUND` (404) if the target is hidden (`:1077-1100`). This is the required ACL non-disclosure behavior for both tree and breadcrumb clients.
- Folder create trims and validates names, checks `CREATE_CHILD`, rejects active sibling name collisions with 409, seeds closure rows, and starts at version 1 (`backend/src/ima/application/authorization.py:1102-1183`). Rename requires `expected_version`, protects roots, increments version, and rejects duplicate sibling names (`:1213-1287`).
- Move locks source and destination, requires `MOVE` on source plus `CREATE_CHILD` on destination, rejects stale version, checks the closure table for a cycle, rejects duplicate destination sibling names, rewrites closure rows, and recomputes ACL anchors (`backend/src/ima/application/authorization.py:1289-1433`). Cycle error is 400 `FOLDER_CYCLE`; stale mutation is 409 `VERSION_CONFLICT`.
- Reorder clamps the requested order to the active sibling range and increments the target version (`backend/src/ima/application/authorization.py:1435-1533`). Trash and restore cascade lifecycle/version changes to the closure subtree; restore validates original parent existence, ACL, and name conflicts (`:1535-1680`). Permanent delete refuses active folders, stale versions, or non-empty subtrees (`:1681-1727`).
- Migration `20260825_0003_workspace_authorization.py:14-97` is additive and idempotent (`IF NOT EXISTS`), creates `ima.folders`, closure, ACL, and migration checkpoint tables, adds a partial active sibling-name uniqueness index (`:53-96`), and preserves legacy public tables. Downgrade deliberately refuses to destroy populated target rows (`:102-118`).
- The existing PostgreSQL integration test applies Alembic twice before exercising authorization (`backend/tests/integration/test_postgres_authorization.py:111-130`). It covers ACL hiding and 404 behavior (`:135-208`), closure correctness after moving a nested folder (`:217-238`), and cleanup/empty target deletion after trashing/deleting a folder (`:322-377`). It does not yet cover API-level file/note/tag migration or browser tree behavior.

### Generated client, transport, coexistence, and test harness

- The checked OpenAPI document and generated TS already contain folder operations, including list/create/get, ACL, breadcrumbs, move, reorder, restore, and trash (`frontend/generated/openapi.json:7046-7773`; generated operation names in `src/api/generated/schema.ts:5199-5619`). `src/utils/identity-client.ts:20-42,63-72,134-166` defines typed DTO aliases and a handwritten `fetch` client with credentials, CSRF for mutations, URL encoding, and `ProblemDetails`-like `{detail,code}` mapping.
- The transport currently casts JSON to the requested type rather than runtime-decoding it (`src/utils/identity-client.ts:63-72`) and the standalone `IMAClient` does the same for success and error payloads (`src/api/ima-client.ts:16-27`). A knowledge API migration needs one shared decoder/adapter if runtime validation is part of acceptance; local casts in each component would violate `.trellis/spec/frontend/openapi-client-contracts.md:15-31`.
- Python is mounted only for exact path families in Caddy (`Caddyfile:15-28,63-81`); `/api/*` otherwise falls to Bun (`:43-46`), and `/api/zero*` is forbidden (`:36-41,88-90`). Workspace folder routes are already included in the Python matcher, while file/item/note/tag endpoints do not exist in the checked OpenAPI path list (`frontend/generated/openapi.json:3492-8562` contains no knowledge-content resource family).
- OpenAPI export/check is deterministic and generator-owned (`backend/scripts/export_openapi.py:12-16`, `backend/scripts/check_contract.py:12-24`). Backend contract tests assert system paths, operation IDs, and absence of chat capture (`backend/tests/contract/test_openapi.py:12-17`); coexistence tests assert exact Caddy matcher behavior (`backend/tests/contract/test_coexistence.py:4-11`).
- Vue unit tests are limited to `tests/components/**/*.vitest.ts` and use happy-dom (`vitest.config.ts:5-18`). Playwright runs only Chromium Desktop Chrome (`playwright.config.ts:3-13`), with global identity Compose setup (`tests/e2e/global-setup.ts:1-63`). Existing E2E covers workspace ACL and folder creation through `page.request`, including hidden folder 404 (`tests/e2e/identity.pw.ts:81-156`), but does not navigate the knowledge tree or test mobile/keyboard interaction.
- Frontend quality requires `bun test`, `bun run lint`, and a Quasar build (`.trellis/spec/frontend/quality-guidelines.md:10-31`); OpenAPI guidance also requires backend contract checks, generated diff checks, `vue-tsc --noEmit`, Bun tests, PWA/admin builds, and exact Caddy fallback verification (`.trellis/spec/frontend/openapi-client-contracts.md:33-59`).

## Acceptance gaps and decisions to make

1. **Resource boundary is incomplete.** Python exposes folder metadata/lifecycle/ACL only. No versioned endpoints or DTOs exist for files, Markdown notes, note revisions/concurrency, tags, file content/blob upload, full trash listing, restore destination selection, or permanent deletion of content. The migration cannot claim feature parity while only swapping folder queries.
2. **Tree loading contract is undefined.** Existing Vue expects nested Zero children and local recursive flattening; Python exposes one-level `parent_id` listing plus a separate breadcrumb endpoint. Define a query-key/cache model for root/parent pages, a maximum depth policy, continuation/pagination semantics, and stale-response cancellation.
3. **Cursor/order mapping is undefined.** Zero uses `sortPriority` plus `id/name` cursor fields; Python uses integer `orderKey` and `version`. Decide whether API list pagination is offset/cursor/keyset and require deterministic tie-breaking across renames/reorders.
4. **Mutation conflict UX is undefined.** Backend returns 409 for stale folder versions, duplicate names, missing restore destinations, and dependency failures. Vue currently calls Zero mutations with no typed 409 projection, optimistic rollback, reload affordance, or preservation of unsaved note text.
5. **Cycle and drop validation is split.** The legacy UI allows drag/drop to any rendered entity and only Zero server code rejects cycles. The new API must expose destination eligibility or return a typed error; the UI must exclude self/subtree destinations and handle 400 `FOLDER_CYCLE` without losing selection.
6. **ACL non-disclosure must be preserved at every layer.** API list/breadcrumbs intentionally return 404 for hidden folders, while the current UI filters Zero results locally. Do not fetch all workspace folder IDs and filter in Vue; hidden folder IDs, names, ACL entries, breadcrumbs, and note metadata must not leak through list, get, search, restore, or error payloads.
7. **Notes and concurrency have no acceptance contract.** Legacy `page.text` and `pagePatch` exist, but no versioned note DTO or revision API is exposed. Define whole-document ETag/version or patch conflict behavior, autosave debounce/cancellation, recovery after 409, and whether a note under a trashed folder remains readable.
8. **Tags are legacy JSON only.** `conf.tags` is a comma-split string. Define normalized case/whitespace rules, ownership scope, tag list/search, batch edits, versioning, and migration behavior for malformed/non-array legacy values.
9. **Trash semantics differ.** Legacy Zero moves entities to a special trash root and can bulk-delete (`src-shared/mutators.ts:934-985`), while Python folder lifecycle cascades status in place and permanent delete refuses children. Define one cross-resource trash model, retention/list pagination, original-parent restore, conflict behavior, and cleanup ordering for files/blobs/notes/tags.
10. **Mobile and keyboard acceptance is absent.** No keyboard handlers exist in `EntityList.vue` or `FolderTree.vue`; Playwright only tests desktop Chromium. Define roving focus/arrow navigation, Enter/Space activation, context-menu alternative, Escape selection clear, multi-select shortcuts, touch drag/drop fallback, narrow breadcrumb overflow, and mobile upload affordances.
11. **Coexistence and rollback are only partially specified.** Caddy routes workspace paths to Python but all legacy `/api/*` paths remain Bun. A cutover flag, dual-read comparison, per-route rollback, and safe cleanup of Zero tables/cache are not documented. Keep legacy read/mutation available until parity tests pass, and make each migration step reversible or checkpointed.
12. **OpenAPI drift and generated ownership need explicit gates.** Folder schemas are already checked, but new resource paths must update backend contracts, checked JSON, generated TS, handwritten adapter, and consumers in one change. Generated files must not be hand edited; add a failure test for missing operation IDs and a no-diff regeneration step.
13. **Planning artifacts are incomplete.** The task currently has a TBD-only `prd.md` and no `design.md` or `implement.md`; the task is complex enough to require explicit resource contracts, cutover/rollback, and test commands before implementation.

## Executable validation and migration matrix

The following should become named tests or scripted checks. Each row states the minimum layer; API/browser rows should use generated DTOs and the same session/ACL fixtures.

| Area | Fixture / setup | Action | Expected invariant | Layer / command |
|---|---|---|---|---|
| Deep tree | Root plus depth 1, 2, 5, and at least 50 siblings | Load root, expand each level, open deepest folder, refresh | Every visible node has correct parent; no duplicate/missing nodes; breadcrumb is root-to-leaf in stable order | Vue component + Playwright desktop/mobile |
| Tree pagination | 101 active siblings with deterministic order keys and duplicate names differing only by case | Fetch first page, continue until exhaustion, rename/reorder between pages | No duplicates, no skips, stable tie-breaker, no repeated cursor request, and loading/error state is visible | API integration + Vitest query adapter |
| Breadcrumb ACL | Viewer can see root and public child but not private descendant | Request private folder and breadcrumbs | Both return 404/problem without private ID/name/ACL details; public ancestor breadcrumbs remain correct | PostgreSQL + API contract + Playwright |
| ACL list filtering | Viewer/editor/admin fixtures with inherited and independent ACL anchors | List each parent and attempt get/search/restore on hidden subtree | Server response excludes hidden rows; client never receives IDs to filter locally; mutating hidden target is indistinguishable from 404 | PostgreSQL integration + API tests |
| Rename conflict | Two active siblings `Report` and `report`; two clients at version 1 | Rename one to conflicting/stale name | 409 typed code, no partial update, version unchanged on failure, UI reload/retry preserves selection | API integration + Vue unit |
| Move conflict | Source/destination and stale source version | Move with stale version, then current version | First is 409; second succeeds and increments version; cache invalidation refreshes both parent lists | API integration + Vue Query test |
| Cycle rejection | A -> B -> C closure | Move A into C and try self move | 400 `FOLDER_CYCLE`; closure rows and ACL anchors unchanged; UI destination list excludes subtree where possible | PostgreSQL + API + drag/drop E2E |
| Reorder | 3+ active siblings, order keys 0..N-1 | Move first to last, repeat concurrently with stale version | Dense order preserved, only valid version succeeds, list order matches API after refetch | API integration + Playwright |
| Notes happy path | Markdown note under accessible folder | Create/edit/autosave/reload note | Text, metadata, and folder relation persist; generated DTO and cache update without Zero dependency | API integration + Vitest + Playwright |
| Notes concurrency | Two clients load same note version | Save A, save B with stale version | B receives typed 409/ETag conflict; unsaved text remains recoverable; no last-write-wins data loss | API integration + browser E2E with two contexts |
| Notes/trash | Note/file children under folder, then trash folder | Read/list while trashed, restore, delete permanently | Defined lifecycle is consistent for folder and descendants; restore restores original parent or returns typed destination-missing conflict; delete cleans dependent rows/blobs | PostgreSQL integration |
| Tags normalization | Legacy tags with whitespace, duplicate case, malformed JSON | Migrate, list, edit, batch edit, search | Canonical case/trim policy, no duplicate active tags, malformed values are reported/quarantined, ACL follows resource | Migration + API + Vitest |
| Trash pagination | >100 mixed folders/files/notes with timestamps and original parents | List pages, restore selected, permanently delete | Stable cursor, selection survives page load, only authorized rows visible, restore/delete version conflicts are typed | API + Vue unit + Playwright |
| Drag/drop | Nested source and destination, files and folders, touch viewport | Drag folder to valid/invalid destination; drop files; use mobile fallback | Valid move uses versioned API; invalid cycle/ACL errors do not lose source; file upload has progress/idempotency and no duplicate folder creation | Playwright desktop + mobile emulation |
| Multi-select/keyboard | 10 rows and tree nodes | Context-menu, click toggles, Shift/Ctrl/Meta range, arrows, Enter/Space, Escape | Selection state and focus are deterministic; every pointer action has keyboard/touch alternative; batch action sends one typed request where contract allows | Vitest + Playwright desktop/mobile |
| API error projection | Mock 400/401/403/404/409/413/5xx/problem payloads and aborted fetch | Invoke every query/mutation adapter | Generated `ProblemDetails`/error code is retained, cancellation is not shown as failure, unauthorized redirects consistently, optimistic state rolls back | Vitest |
| OpenAPI drift | Change a DTO/path/operation ID intentionally | Run export, check, regenerate TS, then `git diff --exit-code` | Drift check fails before regeneration and is clean after; generated files are untouched manually; no duplicate handwritten DTO | `uv run python backend/scripts/check_contract.py`; `bun run generate:api`; `vue-tsc --noEmit` |
| Migration idempotency | Clean PostgreSQL with legacy workspace/entity fixtures | Run Alembic upgrade twice; run source migration/checkpoint twice; rerun after partial failure | No duplicate folders/ACL/tags/notes; checkpoints preserve status/attempts; source fingerprint detects changed input; legacy rows remain intact | `pytest -m postgres` |
| Migration hierarchy integrity | Legacy deep tree with sibling collisions, cross-workspace parent, cycle, malformed ACL/tags | Run migration | Valid rows import topologically; cycles/cross-workspace/malformed rows are failed with reason and not partially committed; closure and ACL anchors are valid | PostgreSQL migration integration |
| Coexistence cutover | Feature flag off/on, Python unavailable, Zero available/unavailable | Browse and mutate each route under both states | Python outage leaves legacy UI usable while flag is off; flag-on routes fail visibly but do not silently write Zero; rollback restores legacy reads/mutations without data loss | Contract + Playwright + Caddy |
| Residue deletion | Parity test fixture and snapshot of legacy consumers | Remove Zero knowledge-tree consumers, then grep/build | No imports of Zero query/mutator/schema for folder/file/note/tag/trash; no `/api/zero` knowledge route; unrelated chat features still compile and pass | `rg`, `bun run lint`, `vue-tsc`, Quasar PWA build, E2E |

## Caveats / Not Found

- No `design.md` or `implement.md` exists in `.trellis/tasks/08-24-knowledge-tree-vue-api`; `prd.md` requirements and acceptance criteria are still `TBD`. The matrix above is evidence-backed research, not an approved product contract.
- No versioned Python API for file bytes, Markdown notes, note revisions, tags, tag search, content trash listing, or blob cleanup was found in `backend/src/ima/api/v1`, `frontend/generated/openapi.json`, or `src/api/generated/schema.ts`.
- No frontend knowledge-tree Vitest/Playwright tests, mobile Playwright project, keyboard navigation implementation, or Vue Query knowledge-tree composable was found. Existing E2E folder checks use `page.request` and therefore do not validate rendered tree behavior.
- Existing backend tests cover PostgreSQL authorization and migration isolation, but not folder API route status/Problem Details for every mutation, cross-resource content migration, tag/note concurrency, or a full rollback/cutover exercise.
- `src/utils/identity-client.ts` contains a broad handwritten client and already lists folder methods, but it is not a generated transport and performs compile-time casts instead of runtime validation. The migration should consolidate shared request/error/decoder behavior before adding another client.
- The current legacy `entity` schema has no database cycle constraint; cycle safety is implemented in Zero server mutator code and the new Python closure model. During coexistence, both paths must be tested or the legacy path must be disabled for migrated knowledge entities.
- Pagination cursor behavior is observable in code but has no direct unit test. The API contract must specify whether clients may issue concurrent page requests and how mutations during pagination affect ordering.
- `Caddyfile` has separate front/admin matchers but both route `/api/v1/workspaces*` to Python. Any new path family must be added to exact matchers and coexistence tests; broadening `/api/*` would capture legacy Bun routes.
