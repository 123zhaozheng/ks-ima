# 移除工作区概念，知识库升级为一等公民与极简UX重构

## Goal

彻底移除「工作区（workspace）」概念，把「知识库」升级为一等公民：用户可以创建多个知识库、通过分享链接（只读/读写）邀请他人加入。同时全面简化平台：模型配置仅平台管理员可见，MCP 授权改为用户级（可查询用户名下全部知识库），个人设置与账户合并为单页，整体走苹果式极简风格。

## Context

- 项目未上线，**所有现有数据可以丢弃**，允许重置数据库、改写迁移历史。
- 现状：一个工作区 = 一个知识库（1:1 容器），成员/文件夹/文档/标签/回收站/向量索引/对话/模型分配/MCP 授权全部以 `workspace_id` 为作用域键。
- 已有的邀请机制（邮件邀请 + 角色）整体删除，替换为全新的便捷分享链接体系。

## Requirements

### R1. 彻底移除工作区概念
- 数据库表/列、后端代码、API 路径、前端代码、i18n、文档中不再出现工作区语义，统一为「知识库 / knowledge base / kb」。
- 用户可以在「知识库」下创建多个知识库、自由切换。
- 每个知识库保留：文件夹树、文档/笔记、文件上传摄取、向量检索、接地问答、对话历史。

### R2. 知识库分享（新体系，替代旧邀请）
- 知识库拥有者可以创建分享链接，指定权限：**只读** 或 **读写**。
- 其他用户打开链接即可加入该知识库（只读→viewer，读写→editor）。
- 分享链接可撤销、可列表查看；保留 token 哈希落库的安全模式。
- 旧的邀请机制（`workspace_invitations`、邮件邀请、邀请接受页）整体删除。
- 简化成员角色为三档：owner / editor / viewer。删除 knowledge_manager 角色、用户组（groups）、文件夹级 ACL——普通用户不再接触这些复杂概念。
- 拥有者可在知识库内管理成员（查看、调整权限、移除）。

### R3. 模型配置仅管理员可见
- 普通用户前端应用（front）中不存在任何模型配置入口（移除 `/workspace/models` 路由、页面、菜单项）。
- 模型配置（网关/治理模型/能力档案/分配）仅存在于 admin 应用，服务端权限校验保持。

### R4. MCP 用户级授权
- OAuth 授权（grant）绑定用户而非单个知识库；删除授权的单工作区绑定与文件夹根限制。
- 外部 MCP 客户端可枚举该用户名下的个人知识库 + 他人分享给他的知识库（`kb_list_knowledge_bases`）。
- 每个工具调用实时校验成员资格与角色：写操作要求 editor 及以上。
- 服务主体（service principal）同样改为用户级（归属于创建者，可访问其全部知识库）。
- OAuth 同意页简化：不再选择工作区/文件夹，只选 scope。

### R5. 个人设置与账户合并
- 侧边栏只保留一个「设置」入口，页面内分区：个人资料（名称/邮箱）、安全（密码/会话/两步验证）、偏好（语言/发送键）。
- 删除 `/account`、`/account/security` 独立路由与冗余入口。

### R6. 极简苹果风格
- 导航精简：Ask、知识库、历史、连接器、设置（+ 管理员可见的管理台入口）。
- 删除「工作区管理」分组（Overview/Tags/Models 子项）；标签管理、回收站从用户界面移除（简化，删除即时生效并确认）。
- 知识库的成员与分享管理收纳在知识库内的简洁管理入口。
- 视觉延续现有 Apple 风格设计语言（参考 `.trellis/spec/frontend/ux-design-language.md`）。

## Acceptance Criteria

- [ ] 全仓库（前后端代码、迁移、i18n、文档）grep 不到残留的工作区语义（合理的英文单词除外，需在 check 中确认语义已消除）
- [ ] 全新初始化数据库可完成：创建用户 → 创建 2 个知识库 → 切换
- [ ] 拥有者创建只读分享链接 → 另一用户通过链接加入 → 该用户只能查看不能编辑；读写链接则可编辑
- [ ] 撤销分享链接后无法再加入；已加入成员不受影响
- [ ] 普通用户界面没有任何模型配置入口；admin 应用模型配置正常
- [ ] MCP 客户端完成一次 OAuth 授权后，`kb_list_knowledge_bases` 返回用户自建 + 被分享的全部知识库；对只读知识库的写工具调用被拒绝
- [ ] 「设置」为单一入口单页分区，`/account` 路由不存在
- [ ] 前端构建（front + admin）、后端测试、前端测试全部通过

## Constraints

- 未上线：数据可丢，迁移历史可改写，无需向后兼容。
- 保持现有分层架构（api / application / domain / infrastructure）与 OpenAPI 契约生成流程（后端导出 → 前端生成类型）。
- 安全底线不降级：分享链接仍存 token 哈希、MCP 仍走 OAuth 2.1 + PKCE、scope 校验保留。

## Out of Scope

- 知识库内细粒度权限（文件夹级共享、用户组）——明确删除而非迁移
- 邮件邀请、用户组管理
- 模型治理后端逻辑本身的改动（仅前端入口治理）
