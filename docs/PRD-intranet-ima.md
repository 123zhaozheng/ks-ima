## 0. 这份 PRD 怎么写、怎么读

这不是一份从零想象功能的传统 PRD，而是一份 **产品改造 PRD**：把现成的 Nya AI 收成内网 IMA。

写作原则（调研结论，已用于本文）：

1. **先写任务，再写功能。** 一句任务定义卡住范围，避免又做成「全能协作套件」。
2. **KEEP / CUT / TRANSFORM / ADD 四象限先于功能清单。** 改造型产品最大风险是「该删没删、该加加歪」。
3. **AI 需求必须有输入契约、输出契约、异常降级、验收标准。** 不能只写「智能问答」。
4. **MCP 是一等公民，不是插件市场。** 本产品是 MCP **服务端**（被其他 agent 连接），不是 MCP **客户端**（去连别人的插件）。
5. **内网边界写进非目标，而不是写进「以后再说」。** 凡是会打到公网的能力，默认删除。
6. **目录是产品骨架，不是侧边栏装饰。** IMA 的文件夹 + 标签、Nya 的嵌套实体树，都要落到信息架构。

## 1. 一句话任务定义

**内网员工**在**不能出公网**的环境里，把部门资料放进**可浏览的目录树**，用 **AI 基于私域知识回答并溯源**；同时把同一套知识以 **MCP 工具**暴露出去，让公司里其他 agent 助手通过**连接器**读写知识库，而不是把知识再复制一份。

当前主要成本：资料散落在网盘/邮件/Wiki，公网 IMA 不能用，现有 Nya AI 又绑了搜索、发布、翻译、MCP 插件等互联网能力。

AI 需要帮到哪一步：

- 人：在目录里找、读、写、问，答案必须带来源。
- 其他 agent：用标准 MCP 工具完成同等的搜、读、写、问，权限不高于签发凭证的人。

## 2. 背景与问题

### 2.1 为什么对标 IMA

腾讯 IMA 的核心不是「又一个 ChatGPT」，而是 **知识生命周期**：

```
入库（多格式解析） → 管理（文件夹 + 标签 + 权限） → 应用（RAG 问答 + 写作）
```

公开资料里，IMA 还叠加了公域能力：知识库广场、知识号、微信公众号导入、全网搜索、Skills/MCP 广场。这些对内网是负担，不是资产。

IMA 真正值得抄的是：

| IMA 能力 | 为什么有潜力 | 内网取舍 |
|---|---|---|
| 知识库为中心，而不是聊天为中心 | 企业资料是资产，对话是入口 | **保留并强化** |
| 文件夹（物理归属）+ 标签（逻辑关联） | 过百份资料仍能定位 | **保留目录，补标签** |
| 基于知识库问答 + 原文溯源 | 能用、敢用、可审计 | **作为 AI 主路径** |
| 共享知识库 + 分级权限 | 部门知识可协作不可外泄 | **保留工作区成员模型** |
| Agent Interface / OpenAPI / MCP | 知识变成其他 agent 的工具 | **作为对外主接口；不做插件市场** |
| 笔记 + 文件双载体 | 人写的和人传的都要进库 | **轻量 Markdown 笔记 + 文件** |

IMA 明确不抄的：

- 知识库广场、知识号、公域订阅
- 微信/公众号导入、网页 URL 入库
- 全网搜索、公众号检索
- Skills 广场、MCP 插件市场（我们是 **提供方**，不是 **消费方**）
- 多端公网同步生态

### 2.2 现状：Nya AI 已经接近「可改的 IMA」

Nya AI 不是空壳。它已经有 IMA 最难做的那一层：**工作区 = 文件系统式目录树**，文件夹里可以放不同类型实体。

当前实体类型：

`folder | chat | search | channel | assistant | provider | mcpPlugin | page | translation | item | shortcut`

 complementary 能力：

- 目录可嵌套；目录级配置可向下覆盖（助手、模型等）——这是比 IMA 更强的一点，**必须保住**。
- 工作区全文检索（PostgreSQL `tsvector`），覆盖对话、频道、页面、翻译、文件文本。
- 内置「工作区搜索」插件，让对话里的模型去搜当前工作区。
- 文件实体 `item` + blob 存储。
- 类 Notion 的 `page`（TipTap + CRDT 协作 + 版本补丁）。
- MCP **客户端**：`mcpPlugin` 去连接外部 MCP；内置 `web`（SearXNG + Jina）、`gread`（GitHub）。
- 公网发布（`pubRoot`）、翻译、频道、Stripe/微信支付套餐。

### 2.3 核心矛盾

Nya AI 的产品叙事是「AI 聊天客户端 + 协作平台 + 可发布到公网」。

内网 IMA 的产品叙事必须改成：

> **私域知识操作系统**：目录是骨架，笔记和文件是血肉，对话是入口，MCP 是对外神经。

## 3. 产品定位

### 3.1 我们是什么

面向内网的 **知识库工作台**：

1. 人在浏览器里管理目录、笔记、文件，并与基于本库的 Copilot 对话。
2. 其他 agent（Cursor、内部助手、自研 Agent）通过 **连接器** 调用本系统的 MCP 工具，把本库当成它们的知识工具箱。

### 3.2 我们不是什么（非目标）

- 不是公网 SaaS，不做注册转化、套餐购买、内容广场。
- 不是即时通讯。频道删除后，协作走「共享知识库 + 评论/对话」，不做群聊。
- 不是 Notion。不做实时多人光标、块协同、公网发布。
- 不是 MCP 插件市场。用户不能在产品里「安装一个外部 MCP」。
- 不是全网搜索引擎。模型不得调用 SearXNG / Jina / GitHub / 任意公网 URL 抓取。
- 不是翻译产品。

### 3.3 已锁定决策（2026-08-21）

| 决策 | 结论 |
|---|---|
| 删除范围 | Pages（Notion 协作页）+ MCP 插件页 + 公网发布，一并删除 |
| 知识写作 | **轻量 Markdown 笔记 + 文件目录**，对标 IMA，不做 Notion 编辑器 |
| 对外 MCP | **全套 CRUD**：列目录 / 搜索 / 读文件 / 写笔记 / 上传 / RAG 问答 |
| 网络边界 | **模型只走内网网关**；其余公网能力全部删除 |

补充默认（若需推翻，改文档版本）：

- 「翻译频道」= **翻译 + 频道** 都删。
- 工作区多人协作保留（owner/admin/member/guest）。
- 套餐支付（Stripe / 微信）删除；额度可做成内网配额，不做收款。

## 4. 用户与场景

### 4.1 角色

| 角色 | 描述 | 主路径 |
|---|---|---|
| 知识管理员 | 部门文档负责人 | 建库、建目录、上传、定标签规范、发 MCP 凭证 |
| 知识消费者 | 普通员工 | 浏览目录、搜索、问 Copilot、读笔记 |
| 外部 Agent | 公司其他助手 | 用连接器调 MCP：搜、读、写、问 |
| 平台管理员 | 运维 / IT | 部署、配内网模型网关、管用户、看审计 |

### 4.2 关键场景（验收用）

**场景 A · 入库**  
管理员把「2025 年制度汇编.pdf」和一则 Markdown 解读笔记放进 `制度 / 2025 /`，打标签 `#制度 #生效中`。文件解析完成后可搜到正文。

**场景 B · 人问**  
员工问：「试用期离职补偿怎么算？」Copilot 只根据知识库回答，列出引用笔记/文件及片段；库中没有则明确说「知识库未收录」，禁止用公网常识硬编制度条款。

**场景 C · 目录导航**  
员工不搜，只点目录：`制度 → 2025 → 薪酬`，看到文件和笔记列表，点开笔记阅读。

**场景 D · Agent 连接器**  
研发把本系统配进内部 Agent：`https://ima.corp.local/mcp` + API Key。Agent 调用 `ask_knowledge` 拿带引用的答案；调用 `create_note` 把会议纪要写入指定文件夹。

**场景 E · 工作区角色**  
guest 能问和读自己被授权的范围，不能上传、不能建连接器。API Key 的权限不大于创建者当前权限；被禁用的 Key 立即失效。

**场景 F · 目录级隔离（内网刚需）**  
部门知识库里有 `公开制度/` 和 `财务/薪酬密级/`。普通成员能浏览、搜索、问到制度；问「薪酬带宽」时，检索与 Copilot **不得命中**财务文件夹，引用里也不能出现该目录标题。财务组成员可以。MCP Key 即使是读写，若绑定的是普通成员，同样问不到。

| 从 | 到 |

## 6. 信息架构与目录设计

这是产品骨架。目标体验：**打开工作区就像打开一个会思考的网盘**。

### 6.1 三层结构

```
工作区 Workspace          ≈ IMA 的一个知识库
 └─ 文件夹 Folder*        ≈ IMA 文件夹（物理归属，可嵌套）
     ├─ 笔记 Note         ≈ IMA 笔记（人写的 Markdown）
     ├─ 文件 File         ≈ IMA Media（上传的 PDF/Word/PPT/图片…）
     ├─ 对话 Chat         ≈ Copilot 会话（可放在目录里，便于按项目归档）
     └─ 文件夹 …
标签 Tag                  ≈ IMA 标签（逻辑关联，不属于树）
```

工作区仍是成员边界和配额边界；**细粒度授权在文件夹上**（§10.3）。一个人可以有多个工作区（个人库 / 部门库）。

### 6.2 为什么保留 Nya 的树，而不是重做 IMA 的两套库

IMA 有「笔记」和「知识库」两套容器，再通过「把笔记加入知识库」桥接。这对公网 C 端合理，对内网是认知税。

Nya 的实体树已经能表达「这个项目文件夹里既有制度 PDF、也有解读笔记、还有一次问答」。**一个树更适合内网。**

要向 IMA 对齐的是 **管理动作**，不是双容器：

- 文件夹：唯一物理位置（移动 = 改 `parentId`）。
- 标签：多对多，不移动文件也能按主题收拢。
- 搜索 / AI：树 + 标签 + 正文，三路都能命中。

### 6.3 目录 UX 要求

左侧（或右侧，沿用现布局）目录树：

- 显示文件夹嵌套；笔记、文件、对话用不同类型图标。
- 拖拽移动；同一父级内排序。
- 右键：新建文件夹 / 笔记 / 上传 / 重命名 / 移动 / 标签 / 删除。
- 文件夹可隐藏、可设排序权重（已有，保留）。
- 文件夹可配置默认助手与模型（已有，保留）。子文件夹覆盖父配置。

主区：

- 点文件夹 → 该目录的内容列表（名称、类型、标签、更新时间、解析状态）。
- 点笔记 → Markdown 阅读/编辑。
- 点文件 → 预览（能预览的）+ 元信息 + 「基于此文件提问」。
- 点对话 → Copilot。

顶部全局搜索：当前工作区，可按类型、标签、文件夹范围过滤。

### 6.4 标签规则

- 工作区级标签；名称唯一（大小写不敏感）。
- 一个实体可打多个标签。
- 点击标签 → 虚拟列表（不改变物理目录）。
- 创建/重命名/合并标签是管理员动作（member 默认可打已有标签，不可删标签定义——可配置）。

### 6.5 改造后允许出现在目录里的类型

| 类型 | 目录可见 | 说明 |
|---|---|---|
| `folder` | 是 | 目录 |
| `note` | 是 | 新；替换 `page` |
| `item` | 是 | 文件 |
| `chat` | 是 | 按项目归档的对话 |
| `assistant` | 配置区，不进普通资料树 | 可放工作区「系统」文件夹或设置页 |
| `provider` | 同上 | 仅管理员 |
| `shortcut` | 可选 | 快捷入口 |
| `search` | 否，改为全局搜索页 | 不再当树节点也能用 |

删除后不再出现：`page` `translation` `channel` `mcpPlugin`。

### 6.6 新建菜单（改造后）

只留：

- 文件夹
- 笔记
- 文件（上传）
- 对话

管理员设置里另有：助手、模型供应商、连接器。  
**不要出现：翻译、频道、页面、MCP 插件、发布。**

## 7. 功能需求

### 7.1 工作区

- 创建 / 重命名 / 归档工作区。
- 邀请成员、角色：owner / admin / member / guest（角色默认能力见 §10.2）。
- 目录 ACL 见 §10.3：同一工作区内可以按文件夹再收权。
- guest：默认只读 + 可提问（仍受目录 ACL 限制）；不可上传、不可改 ACL、不可创建 API Key。
- 工作区级开关：`允许外部 MCP`（默认开）。关掉后已有 Key 全部失效。

### 7.2 笔记（P0，替换 Page）

**定位：** 一人编辑的 Markdown 笔记，用来写制度解读、会议纪要、FAQ。不是协作文档。

必须：

- 标题 + Markdown 正文；常见快捷语法；代码块；图片（工作区内文件引用，不外链公网图床）。
- 自动保存；冲突策略：后写覆盖并提示「已有更新」（V1 不需要 CRDT）。
- 属于某个文件夹；可移动、打标签。
- 进入全文检索；可被 RAG 引用。
- 导出 `.md`。

不要：

- 实时多人编辑、评论气泡、公网分享链接、Slash 命令生态、docx 往返（docx **导入成笔记**可放 P1）。

存储建议：新表 `note(id, rootId, text, search)`，不要复用 `pagePatch` 流水。V1 不做版本树；P2 再加「保存版本」。

编辑器：优先用仓库已有 `md-editor-v3`，拆除 TipTap 协作链路（可分阶段，但产品上 Page 入口必须消失）。

### 7.3 文件

- 上传到当前文件夹；保留类型不限、大小走工作区限额。
- 可解析类型（PDF / DOCX / PPTX / TXT / MD / HTML 等）抽取文本进 `item.text`，进检索。
- 解析状态对用户可见。
- 不提供「从 URL 导入」「从公众号导入」。
- 图片 OCR：P2；V1 不承诺。

### 7.4 Copilot 对话

对话是知识应用入口，不是产品中心。

系统约束（产品规则，不是文案）：

1. 默认启用「知识库」工具（原 workspace 插件的升级版）。
2. **禁止** web-search、web-crawl、GitHub、用户自定义 MCP。
3. 回答涉及制度、数据、内部事实时：**必须引用**；无检索命中则声明知识库没有，可给「建议补充到哪一目录」的空态，不得用模型世界知识冒充库内规定。
4. 通用闲聊（如「这句话语法对不对」）允许不检索。
5. 引用可点击，打开对应笔记/文件并尽量高亮片段。
6. 检索语料 = 当前用户 `view` 集合；无权限 chunk 不得进入 prompt（§10.4）。

保留：消息分支、流式、附件进对话（附件同时可另存到目录，P1）。

### 7.5 人用搜索

- 关键词搜索当前工作区：笔记、文件正文、对话、文件夹名、标签名。
- 过滤：类型、标签、所在文件夹（含子孙）。
- **结果必须先过 `view` ACL**，再排序高亮。无权限文档不得因关键词命中而露标题。
- 高亮片段（现有 `ts_headline` 可沿用）。
- 删除「翻译记录」作为搜索源。

### 7.6 连接器管理页（P0，新页面）

这是「MCP 插件页」的反面：不是去连别人，是让别人连我们。

页面内容：

1. 说明：其他 agent 把本知识库当作工具。
2. 创建连接器：名称、备注、绑定工作区、可选绑定**文件夹根**（只暴露该目录及子孙）、权限范围（只读 / 读写）、过期时间。
3. 只显示一次的 API Key；之后仅可吊销/轮换。
4. 一键复制：
   - MCP 配置 JSON（Cursor / Claude Desktop / 内部 Agent 模板）
   - 服务 URL：`{ORIGIN}/mcp`
5. 调用统计：最近使用时间、次数、最后工具名（P1）。

权限：仅 owner/admin 可创建。Key 权限 ≤ 创建者在该工作区的权限。

### 7.7 管理后台改造

删除：默认翻译模型、搜索引擎列表、套餐价格、Stripe/微信。

保留：用户、工作区、模型、默认对话模型、存储限额。

增加：MCP 是否全局启用、embedding 网关配置（P1）、审计查看（P1）。

## 8. AI 专属需求

### 8.1 模型故事

模型在本产品里只扮演 **「有权限的图书管理员」**：

- 能看的，只有当前用户（或 API Key 映射用户）被授权的工作区内容。
- 先找再答；找不到就说找不到。
- 不联网、不调用外部插件、不把内容发到公网。

### 8.2 输入契约

问答请求必须能构造出以下上下文，缺一不可则降级：

| 输入 | 来源 | 缺失时 |
|---|---|---|
| 用户问题 | 对话或 MCP `question` | 拒绝 |
| 工作区 ID | 当前工作区或工具参数 | 拒绝 |
| 权限范围 | session 用户 ∩ 目录 ACL ∩ Key 范围 | 拒绝 |
| 可见实体集合 | `can(actor, entity, view)` 的结果 | 检索空间为空则走无命中 |
| 可选：文件夹 ID、标签、类型 | UI 或工具参数 | 在**可见集合**内再收窄 |
| 检索结果 | FTS（V1）/ 混合检索（P1） | 走「无命中」模板 |
| 当前时间 | 服务器 | 必带，避免过期制度被当成现行 |

禁止当作输入：

- 任意 URL 抓取结果
- 公网搜索结果
- 无权限实体

### 8.3 输出契约

人用对话：

```text
[直接回答，内部事实必须能在引用中找到]

引用：
1. 《笔记或文件标题》 / 路径 / 片段摘要
2. …
```

MCP `ask_knowledge` 必须同时返回结构化字段，不能只有一段 Markdown：

```json
{
  "answer": "string",
  "citations": [
    {
      "entityId": "…",
      "type": "note | item",
      "title": "…",
      "path": "制度/2025/薪酬.md",
      "quote": "原文片段",
      "score": 0.0
    }
  ],
  "knowledgeGap": false
}
```

规则：

- `knowledgeGap=true` 时，`answer` 必须说明未收录，`citations` 可为空或仅为「相关但不充分」。
- 禁止输出公网链接作为依据。
- 关键数字、条款必须出现在至少一条 `quote` 中，否则视为不合格（测试集要覆盖）。

### 8.4 检索策略

**V1（必须交付）**

1. 对问题生成 1～3 条查询（可规则或小模型）。
2. 工作区内 FTS，类型限 `note`、`item`，可选 `chat`（默认关，避免把闲聊当制度）。
3. 取 Top K 片段交给生成模型，并规定「只根据下列资料回答」。

**P1**

- 内网 embedding 网关对笔记/文件切片向量化。
- 混合检索：关键词 + 向量，再重排。
- 切片粒度：按标题/段落，单 chunk 建议 400～800 字，重叠 50～100 字。

对标 IMA 架构（公开技术文）：外部格式 → 统一 Media（展示）→ Chunk（RAG）。我们对应：

- Media ≈ `entity` + `note`/`item`
- Chunk ≈ 新表 `chunk(entityId, ordinal, text, embedding)`

入库要异步：上传/保存 → 入队 → 解析 → 写文本/chunk → 状态就绪。不要让 HTTP 同步等大 PDF。

### 8.5 异常与降级

| 情况 | 行为 |
|---|---|
| 检索 0 命中 | 固定「知识库未收录」+ 建议补充路径；`knowledgeGap=true` |
| 解析未完成 | 标明该文件暂不可问；可问已就绪部分 |
| 模型网关失败 | 返回系统错误，不改用公网备用模型 |
| 引用实体已删 | 丢弃该引用，必要时重检索 |
| 权限不足 | 当不存在处理，不泄露标题 |
| MCP 参数越权 | 工具错误：`forbidden` |

### 8.6 质量与验收（可测试）

准备 ≥ 30 条「问题–应引文档–不应出现的幻觉点」黄金集，覆盖：

- 条款原文问答
- 跨文件夹但同标签
- 无相关文档
- guest 越权问
- 文件还在解析中

门槛（V1 可先人工评，P1 自动化）：

- 有据事实题：关键事实可在 citations 中找到 ≥ 90%
- 无据题：不得编造内部规定 ≥ 95%
- 越权题：不得出现无权限标题 100%

## 9. 对外 MCP 工具接口（连接器）

### 9.1 原则

- 本系统 **只提供** MCP，**不安装** MCP。
- 传输： **Streamable HTTP**（内网服务，适合连接器）。可选 SSE。不做「让用户在 UI 里填一个外部 MCP URL」。
- 鉴权：`Authorization: Bearer <api_key>`。
- 所有工具在服务端做 ACL；Key 只读则写工具对客户端不可见或调用即 `forbidden`。
- 工具命名稳定，加前缀 `kb_`，避免和调用方本地工具撞名。

### 9.2 对标 IMA Agent Interface，内网裁剪

IMA 官方/社区暴露的能力大致是：笔记列表/读写/检索，知识库列表/检索/详情，上传文件，**导入 URL**。

我们：

- 对齐读写与检索。
- **永不提供** `import_urls`、网页收藏、公众号导入。
- 用「工作区 + 目录路径」替代 IMA 的「笔记空间 / 知识库」双 ID 体系，降低连接器心智。

### 9.3 工具清单（V1 全套 CRUD，已锁定）

#### 发现

| 工具 | 权限 | 作用 |
|---|---|---|
| `kb_list_workspaces` | 读 | 当前 Key 能访问的工作区 |
| `kb_list_dir` | 读 | 列出某文件夹子项（id、类型、名称、标签、更新时间、解析状态） |
| `kb_get_tree` | 读 | 浅树或有限深度树，防止一次拉爆 |

#### 读

| 工具 | 权限 | 作用 |
|---|---|---|
| `kb_search` | 读 | 关键词搜索；过滤类型/标签/文件夹 |
| `kb_get_note` | 读 | 笔记全文 + 路径 + 标签 |
| `kb_get_file` | 读 | 文件元信息 + 已解析文本（不回传二进制；另提供下载 URL 若只读需要） |

| 工具 | 权限 | 作用 |
|---|---|---|

## 10. 权限、安全、内网边界

> v0.1 只写了工作区四角色，**不够**。Nya 现状也是「进了工作区 ≈ 能看全部内容」（`withReadable` = 任意成员；`withWritable` = owner/admin/member）。`entityAccess` 只是最近打开记录，不是 ACL。  
> 内网知识库的真实需求是：一个部门库里仍有密级目录；**搜索、Copilot、MCP 必须共用同一套权限网关**，否则 AI 会成为泄密口。本节为 v0.2 重写。

### 10.1 设计原则

1. **默认拒绝，显式授予。** 未授权实体在列表、搜索、问答、MCP、下载里都当作不存在，不返回标题、路径、引用。
2. **目录是授权单元。** 跟 IMA/网盘一样，权限跟文件夹走，子项默认继承；需要时打断继承。笔记/文件 V1 不单独设 ACL（避免授权爆炸），跟所在文件夹走。
3. **一条网关走完全部读路径。** UI 浏览、全文检索、向量检索、`kb_ask` 引用拼装、文件下载、MCP 工具，全部调用 `can(user, entity, action)`。禁止「先检索再过滤」让模型看见无权限 chunk。
4. **MCP 不能提权。** Key 的有效权限 = 创建者权限 ∩ Key 声明范围（工作区 / 文件夹根 / 只读|读写）。创建者后来被降权，Key 跟着降；被移出工作区则 Key 失效。
5. **问 ⊆ 看。** 能对某文档提问，就必须有 `view`。否则引用要么泄密要么无法溯源。禁止「不能看原文但能问出原文」。
6. **平台管理员 ≠ 知识库读者。** 后台 `isAdmin` 能管用户和模型，默认**不能**读各工作区正文；要读必须是该工作区成员（可另开「紧急审计」开关，P1，全量记审计）。

### 10.2 工作区角色（默认能力）

角色仍是四个，表示「没打断继承时，对工作区根目录的默认授权」。

| 动作 | guest | member | admin | owner |
|---|---|---|---|---|
| `view` 读目录/笔记/文件 | ✓ | ✓ | ✓ | ✓ |
| `ask` 基于可见范围提问 | ✓ | ✓ | ✓ | ✓ |
| `edit` 新建笔记、上传、改可见范围内的笔记/文件 | | ✓ | ✓ | ✓ |
| `delete` 删到回收站 | | 自己创建的 | ✓ | ✓ |
| `manage` 改该层 ACL、移动进/出本文件夹 | | | ✓ | ✓ |
| 工作区成员与角色 | | | ✓ | ✓ |
| 创建/吊销连接器 | | | ✓ | ✓ |
| 转让 owner / 删除工作区 | | | | ✓ |

说明：

- member 默认可改**自己有 `edit` 的文件夹里**的笔记（含别人写的）。这是部门库协作默认值。若某文件夹只许作者改，打断继承后只给本人 `edit`。
- guest 即使在工作区里，也只对「默认继承链上仍授予 guest」的目录可见。密级目录打断继承且不授 guest 后，guest 完全不可见。

### 10.3 目录 ACL（P0）

授权对象挂在 **文件夹** 上。

```
工作区根  ──继承──► 公开制度/  ──继承──► 2025/
                └──打断──► 财务/  ──继承──► 薪酬密级/
```

每条 ACE：

| 字段 | 含义 |
|---|---|
| `folderId` | 文件夹实体 |
| `principalType` | `role` 或 `user`（P1 再加 `group`） |
| `principalId` | `guest`/`member`/… 或 userId |
| `actions` | `view` `ask` `edit` `delete` `manage` 的子集 |
| `inherit` | 本文件夹是否继续吃父级 ACL；`false` 即打断 |

计算规则：

1. 从目标实体走到根，找到最近的「打断点」（含自身若为文件夹且打断）。
2. 该点的 ACE ∪ 从该点到目标之间「未打断」的追加 ACE（V1 简化：**打断后只看打断点上的 ACE**，不再和父级合并。更易懂，也更安全。）
3. 用户有效动作 = 其工作区角色对应 ACE ∪ 点名到该用户的 ACE。
4. owner 对整库永有全部动作，不能被文件夹 ACL 拿掉（避免把自己锁死）。紧急例外：owner 可被平台管理员撤掉成员身份。
5. 移动文件夹：带着自己的 ACL 走；继承关系改挂新父节点。若用户对目标父文件夹没有 `edit`，禁止移入。

UI：

- 文件夹右键「权限」。
- 默认展示「继承自上级」；可「使用独立权限」。
- 独立权限下：按角色勾选，并可「添加成员」。
- 必须能预览「这些用户将失去访问」（打断前确认）。

V1 不做：文档级 ACE、动态组、审批流、水印强制。P1 可加用户组（对齐部门）。

### 10.4 统一权限网关（所有读路径）

伪代码级产品约束，实现必须等价：

```
can(actor, entity, action):
  actor = session 用户 或 API Key 映射用户
  若无工作区成员身份 → deny
  若 Key 声明了 folderRoots 且 entity 不在这些子树内 → deny
  若 Key 为只读且 action ∈ {edit, delete, manage} → deny
  若 actor 为 owner → allow
  解析 entity 所在文件夹的有效 ACL
  若 action 不在有效动作里 → deny
  allow
```

强制接入点：

| 路径 | 不满足时 |
|---|---|
| 目录列表 / 树 | 子项直接不出现 |
| 打开笔记/文件 | 404 同款「不存在」，不说「没权限」 |
| 下载 / 预览 URL | 401/404 |
| 全文检索 SQL | `entity_id IN visible_ids`（或 ACL 表 join），在 rank 之前过滤 |
| 向量检索 | chunk 关联实体必须先过 `view`；**禁止**把无权限 chunk 送进 prompt |
| Copilot / `kb_ask` 引用 | 每条 citation 再验一次 `view` |
| MCP `kb_list_dir` / `kb_get_*` / `kb_search` / `kb_ask` | 同上 |
| 移动 / 删除 / 改 ACL | 验源与目标两侧 |

越权探测验收：

- 无权限文件夹的标题不得出现在搜索、问答、引用、MCP 返回、报错信息。
- 黄金集加「薪酬密级」对抗题，普通成员问中关键词，命中率必须为 0。

### 10.5 连接器（MCP）权限

创建连接器时声明三层范围，生效时取交集：

```
有效权限 = 创建者当前权限
         ∩ Key.workspaces
         ∩ Key.folderRoots（可选，默认整库但仍受目录 ACL）
         ∩ Key.mode（read | readwrite）
```

| 规则 | 要求 |
|---|---|
| 谁能创建 | 仅 admin / owner |
| 只读 Key | 工具列表不出现写工具，或调用即 `forbidden` |
| 文件夹根 | `kb_list_workspaces` 仍可见库名；`kb_list_dir` 从该根开始；根之外 id 一律当不存在 |
| 轮换 / 吊销 | 立即生效；已建立的 MCP 连接下次请求失败 |
| 创建者降权或退库 | Key 失效或降到其新权限，不能继续读密级目录 |
| 审计 | 每次 tool 记 `keyId + actorId + workspaceId + entityIds` |

禁止：用平台 admin 身份签发「全站万能 Key」。

### 10.6 对话与助手的权限

- 对话本身是实体：默认落在用户「我的对话」目录，仅自己 `view/edit`（系统对个人对话打断继承，不授给全体 member）。
- 若用户把对话移到共享文件夹，则跟该文件夹 ACL 走（可能被同事看见聊天，需在移动时确认）。
- 助手 / 供应商配置：仅 admin/owner `edit`；member 可以使用被授权的模型，不能改网关密钥。
- guest 可以使用 Copilot，但检索范围仍是其 `view` 集合。

### 10.7 身份与会话

V1：现有登录（邮箱）即可，必须登录才能进任何工作区。  
P1.5：内网 OIDC。映射：IdP 组 → 工作区角色或（P1）用户组 ACE。  
删除公网发布后，匿名可读路径必须为零（除登录页）。

### 10.8 与 IMA 的对应

IMA 公开材料是「多级身份 + 统一权限网关 + 从个人到团队演进」。我们不照抄其四级名称，对齐的是机制：

| IMA | 本产品 |
|---|---|
| 知识库级身份 | 工作区角色 |
| 内容/协作权限细化 | 文件夹 ACL + 继承/打断 |
| 统一权限网关 | §10.4 全读路径同一 `can()` |
| OpenAPI Key | 连接器 Key，且不能大于人的权限 |

### 10.9 内网硬约束

部署后默认：

1. 应用服务器不得访问公网。模型、embedding 只指向内网网关。
2. 代码与配置中删除：`SEARXNG_URL`、Jina、gread、Stripe、微信 SDK 调用路径。
3. 用户内容中的 `http(s)://` 只当文本，**不**自动抓取。
4. 发布能力删除后，不存在「不登录可看」的内容路由（登录页除外）。
5. 文件下载 URL 必须鉴权，不可长期裸链到公网。
6. 权限计算只在服务端；前端隐藏入口不算授权。Zero 查询必须带与 `can()` 等价的过滤，防止客户端直连 replica 读到密级行。

### 10.10 审计（P1，V1 至少打日志）

记录：登录、检索、问答、MCP 每个 tool 调用（Key id、工具名、工作区、实体 id）、上传、删除、改 ACL、Key 创建/吊销。  
V1 可写服务器日志；P1 进可查询表。改 ACL 与越权尝试（deny）都要记。

## 11. 数据与技术改造要点

### 11.1 实体与表

新增：

- `note`（替代 `page` 的产品位）
- `tag`、`entityTag`
- `folderAcl`（文件夹 ACE：principal、actions、是否打断继承）
- `connector` / `apiKey`（哈希存储；范围含 workspaceIds、folderRoots、mode）
- `parseJob`（P1）
- `chunk` + 向量列或独立向量库（P1）

删除或停写：

- `translation`、`translationRecord`
- `channel`（及频道消息类型）
- `mcpPlugin`
- `page`、`pagePatch`（迁移策略见下）
- `pubRoot` 相关路径
- `order`、`planPrice`、支付 webhook（plan 表可留作内部限额模板）

### 11.2 Page → Note 迁移

- 开发态/内网新部署：无 Page 数据，直接切。
- 若已有 Page：一次性把 `page.text` 导入 `note.text`，实体 `type` 改为 `note`，丢弃 CRDT 补丁。PRD 默认按此做，不保留双栈。

### 11.3 内置插件只留这些

| ID | 去留 |
|---|---|
| `workspace` → 升级为 `knowledge` | 留，并强化引用 |
| `mermaid` | 留 |
| `web` | 删 |
| `gread` | 删 |
| 用户 MCP | 删 |

聊天侧「插件开关」若只剩知识库 + mermaid，可改成隐式默认开启，减少「插件」心智（推荐）。

### 11.4 技术栈约束

- 继续现有：Vue/Quasar 前端、Hono 服务端、Postgres、Zero、S3 兼容存储。
- MCP：已有 `@modelcontextprotocol/sdk`，改为 **Server** 挂在 Hono。
- 模型：OpenAI 兼容内网网关（vLLM / 公司网关均可）。
- 不要为了「更像 IMA」引入必须出网的依赖。
- **Zero：** `withReadable` 必须从「任意成员可读整库」改为「成员 + 目录 ACL」。Mutator 与 Query 用同一套规则，避免 replica 泄密。

## 13. 里程碑

### M0 · 收口（约 1 周）

- 删除翻译、频道、MCP 插件、发布、web/gread、支付入口与配置。
- 新建菜单与路由只剩目录相关。
- 启动与健康检查不依赖 `SEARXNG_URL`。
- README 改成内网知识库定位。

**验收：** 干净部署后，UI 找不到上述入口；抓包无公网依赖（模型网关除外）。

### M1 · 知识骨架 + 权限网关（约 3 周）

- `note` 上线，Page 入口消失。
- 标签。
- 目录 UX：文件夹列表、拖拽/移动、解析状态。
- **文件夹 ACL（继承/打断）+ `can()` 接入列表/打开/搜索/问答。**
- 对话默认走知识库工具 + 引用展示（语料已过滤）。
- 个人对话目录默认仅自己可见。

**验收：** 场景 A/B/C/F 人工走通；普通成员问密级关键词，引用与答案均不泄露。

### M2 · 连接器（约 2 周）

- API Key + 连接器页（含可选文件夹根）。
- MCP HTTP + §9.3 全部工具，全部走同一 `can()`。
- 只读 Key 无法写入；绑定普通成员的 Key 问不到密级目录。

**验收：** 场景 D/E/F；用 MCP Inspector 跑通工具列表与 ACL。

### M3 · 检索质量（P1）

- 异步解析队列。
- 内网 embedding + chunk + 混合检索。
- 审计查询。

## 14. 测试要点（摘要）

- 回归：工作区邀请、上传、目录移动、回收站。
- 删除回归：翻译/频道/Page/发布/MCP 插件路由 404。
- 出网：单测或契约测试禁止 `web`/`gread` 模块存在。
- 问答：黄金集。
- MCP：只读 Key、过期 Key、跨工作区、append 笔记、回收站删除。
- 安全：无 Key 访问 `/mcp`；下载链接未登录 401。
- **权限：** 打断继承后，无权限用户在 UI / 搜索 / Copilot / MCP / 下载五条路径上都看不到该文件夹标题；owner 不被锁死；移动进无 `edit` 的目录失败；Key 随创建者降权失效。
- **同步层：** 无权限实体不得出现在 Zero replica 订阅结果里。

## 15. 风险

| 风险 | 缓解 |
|---|---|
| 只有 FTS、问答不像 IMA | M1 先引用闭环，M3 上向量；PRD 不假装 V1 已是语义 RAG |
| 拆 Page 伤及编辑器公共代码 | 笔记走 md-editor；TipTap 可后删，产品入口先消失 |
| MCP 上传大文件 | 分片或预签名到内网 S3，工具只提交元数据 |
| 「目录里还能放 chat」变乱 | 默认「新建对话」进仅自己可见的「我的对话」；允许用户挪到项目目录并二次确认 |
| 员工把外链当知识 | 产品文案明确：请上传文件或写笔记，不抓网页 |
| Copilot 泄密（检索先命中再过滤） | 检索前用 ACL 约束；引用再验 `view`；对抗题进黄金集 |
| Zero 本地 replica 绕过服务端 | 查询权限与 mutator 必须等价；禁止客户端写 ACL 表 |

## 17. 成功标准

上线后同时成立：

1. 无公网知识库能力也能完成「上传 → 目录整理 → 带引用问答」。
2. 其他 agent 只配 URL + Key，就能搜、读、写、问同一套库。
3. 代码与配置中不再出现 SearXNG、Jina、gread、公网发布、翻译、频道、MCP 插件实体。
4. 目录仍是第一导航，而不是把产品做成纯聊天框。
5. 同一工作区内密级文件夹对无权限成员、其 Copilot、其 MCP Key 均不可见（含标题）。
